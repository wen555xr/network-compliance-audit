# 01 · 项目背景与需求

## 一、项目背景

企业园区网络通常由成百上千台交换机组成，分属核心、汇聚、接入三个层次。随着网络规模扩大，
设备配置的安全合规性问题日益突出：SNMP 默认社区串未修改、AAA 认证缺失、Telnet/HTTP 等
明文管理服务未关闭、日志未集中收集……这些隐患一旦被利用，将导致设备被非法接管或运维审计失效。

传统的人工逐台登录、逐条比对方式效率低下且容易遗漏。本项目建设一个**可自动运行、可演示**
的「网络设备配置合规性自动审计系统」，用 Python 批量采集设备配置并自动比对合规基线，
输出审计报告与告警，替代人工重复劳动。

## 二、项目目标

1. 在华为 eNSP 上搭建「核心—汇聚—接入」三层园区网络作为审计目标（4 台 S5700 交换机）；
2. 采用符合企业运维最佳实践的管理方式：**管理 IP 通过 VLANIF 虚拟接口配置**（而非物理口），
   SSH 远程登录；
3. 用 Netmiko 批量 SSH 采集设备运行配置；
4. 设计基于正则的配置解析引擎，对关键合规项自动审计比对；
5. 生成 HTML + Excel 双格式审计报告（合规率统计、不合规清单、改进建议）；
6. 合规率低于阈值时触发企业微信机器人自动告警；
7. 代码托管 GitHub，附完整项目文档。

## 三、需求边界

| 项目 | 内容 |
|---|---|
| 仿真平台 | 华为 eNSP（V100R003C00SPC100） |
| 网络设备 | 华为 S5700 系列交换机 ×4（核心 1 / 汇聚 1 / 接入 2） |
| 桥接方式 | eNSP「云（Cloud）」设备 + 宿主机环回适配器 |
| 管理协议 | SSH（STelnet），管理地址走 VLANIF |
| 审计范围 | SNMP 安全、AAA 认证、高危服务端口、日志管理、访问控制（10 项规则） |
| 报告格式 | HTML（自包含）、Excel（openpyxl 三 Sheet） |
| 告警方式 | 企业微信机器人（Markdown 消息） |

## 四、关键设计决策

- **管理 IP 走 VLANIF**：交换机管理地址统一配置在管理 VLAN（VLAN100）的 `Vlanif100` 虚拟接口上，
  符合真实企业网络"业务与管理分离、三层接口承载"的最佳实践，也是 SSH 连接目标。
- **故意埋入合规梯度**：为让审计结果有区分度、报告可读，4 台设备按 100% / 70% / 60% / 30%
  的合规率梯度刻意配置不同数量的违规项（详见 03 文档），从而能真实演示告警触发。
- **规则数据驱动**：10 项规则定义在 `rules.yaml`，规则引擎只负责解释，增删规则不改代码。
- **三模式运行**：`files`（纯离线）/ `mock`（伪 SSH 服务器）/ `ensp`（真实设备），
  保证无 eNSP 环境下也能完整跑通全流程。
