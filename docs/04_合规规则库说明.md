# 04 · 合规规则库说明

合规规则库定义于 `automation/compliance/rules.yaml`，是**数据驱动**的核心：规则引擎只负责解释，
增删规则只需改 YAML，无需改代码。

## 一、规则结构

每条规则包含如下字段：

| 字段 | 说明 |
|---|---|
| `id` | 规则编号（R01~R10） |
| `name` | 规则名称 |
| `category` | 类别（SNMP 安全性 / AAA 认证 / 高危服务端口 / 日志管理 / 访问控制） |
| `severity` | 严重性（high / medium / low） |
| `check_type` | 检查类型（`regex_present` / `regex_absent`） |
| `pattern` | 正则表达式 |
| `description` | 合规条件描述 |
| `remediation` | 修复建议 |

### 两种检查类型

- `regex_present`：配置中**必须出现**该正则，否则判违规（如"SSH 服务启用""日志服务器配置"）；
- `regex_absent`：配置中**一旦出现**该正则即判违规（如"默认社区串""明文 Telnet 服务"）。

## 二、10 项规则详解

| ID | 规则 | 类别 | 严重性 | 检查 | 正则要点 |
|---|---|---|---|:-:|---|---|
| R01 | SNMP 社区串安全 | SNMP 安全性 | high | absent | `snmp-agent community.*(public\|private)` 命中默认串即违规 |
| R02 | AAA 本地认证 | AAA 认证 | high | present | `authentication-mode aaa` 必须存在 |
| R03 | 本地用户密码加密 | AAA 认证 | high | absent | `local-user ... password (simple\|cipher)` 明文/可逆即违规 |
| R04 | 无默认弱口令 | AAA 认证 | high | absent | `admin@123\|huawei@123\|...` 命中弱口令即违规 |
| R05 | SSH 服务启用 | 高危服务端口 | high | present | `stelnet server enable` 必须存在 |
| R06 | Telnet 服务关闭 | 高危服务端口 | high | absent | `\btelnet server enable` 或 `protocol inbound (telnet\|all)` |
| R07 | HTTP 服务关闭 | 高危服务端口 | high | absent | `http server enable` / `web server enable` |
| R08 | 日志服务器配置 | 日志管理 | medium | present | `info-center loghost <ip>` |
| R09 | 日志时间戳使能 | 日志管理 | medium | present | `info-center timestamp (log\|trap\|debug)` |
| R10 | 管理通道 ACL | 访问控制 | medium | present | `acl <n> inbound` 应用到 VTY |

## 三、正则设计要点

1. **词边界防误判**：R06 用 `\btelnet server enable` 而非 `telnet server enable`，
   避免把 `stelnet server enable`（SSH 命令）误判为 Telnet——`stelnet` 末尾恰好包含 `telnet server enable`。
2. **区分可逆/不可逆加密**：R03 匹配 `password (simple|cipher)`，而 `irreversible-cipher`
   因 `password` 后紧跟的不是 `simple`/`cipher`（而是 `irreversible-...`）不会被误判。
3. **大小写不敏感**：规则引擎统一以 `re.IGNORECASE` 编译，兼容 `Http`/`HTTP` 等写法。
4. **证据行**：命中的配置行会作为"证据"写入报告，便于人工复核。

## 四、扩展方式

在 `rules.yaml` 新增一条规则即可（引擎无需改动）：

```yaml
  - id: R11
    name: 未启用闲置端口
    category: 端口安全
    severity: medium
    check_type: regex_absent
    pattern: 'interface GigabitEthernet.*'
    description: ...
    remediation: ...
```

## 五、真实环境注意事项

- 真实华为设备 `display current-configuration` 会把 `cipher` 加密的 SNMP 社区串显示为密文，
  因此 R01 在真实设备上对"已加密但仍是 public"的串可能无法直接命中；
  生产环境更稳妥的做法是直接**禁用 SNMP 或迁移 SNMPv3**，并配合 `display snmp-agent community`
  等命令二次确认。本项目的 `samples/` 按 eNSP 实际显示习惯保留了明文 `public`，用于教学演示。
