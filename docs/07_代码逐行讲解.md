## 〇、先搞懂几个基础概念（后面会反复出现）

### 1. 什么是「导入 import」？
写代码就像搭积木。`import` 就是把别人写好的、或者自己写的**别的文件里的功能**拿过来用。

```python
import re          # 拿 Python 自带的「正则」模块
import yaml        # 拿第三方「yaml 解析」库（读配置文件用）
from netmiko import ConnectHandler   # 从 netmiko 库里拿「连接设备」的函数
```

- `import 模块名` → 用的时候写 `模块名.xxx`，比如 `yaml.safe_load(...)`。
- `from 模块 import 函数名` → 直接用 `函数名(...)`，省得写模块名前缀。

### 2. 什么是「函数 def」？
函数是一段**有名字、可以反复调用**的代码。`def` 是定义（define）的缩写。

```python
def 函数名(参数1, 参数2):
    # 缩进的代码都是函数体
    return 结果     # return = 把结果交还给调用者
```

调用：`函数名(值1, 值2)`。

### 3. 什么是「类型注解」？
`name: str` 这种写法叫**类型注解**，意思是「这个变量应该是字符串」。
Python 运行时不强制检查，它纯粹是**给人看的说明书 + 给 IDE 提示用的**。

```python
def load_devices(inventory_path: pathlib.Path) -> list[dict]:
#                    参数名: 参数类型        -> 返回值类型
```

- `list[str]` = 字符串组成的列表
- `dict` = 字典（键值对）
- `tuple[str, str, str, str]` = 固定 4 个字符串的元组
- `Path | None` = 可能是 Path，也可能是 None（`|` 是 Python 3.10+ 的「或」写法）

### 4. 什么是「@dataclass」？
普通类要写一堆 `__init__` 初始化代码，太啰嗦。`@dataclass` 是 Python 的一个装饰器，
**自动帮你生成** `__init__`（构造函数），只要声明有哪些字段就行：

```python
@dataclass
class Rule:
    id: str
    name: str = ""
```
就等于自动生成了 `Rule(id, name)` 这种构造方式。

- `field(default_factory=list)`：这个字段默认是**一个新列表**。为什么不用 `= []`？
  因为列表是「可变对象」，直接 `= []` 会让所有实例共享同一个列表，会出 bug。`default_factory` 保证每个实例都有自己独立的新列表。**这是面试常问的点**。

### 5. 什么是「列表推导式」？
一行代码生成一个列表，是 Python 最常用的写法：

```python
[ln.strip() for ln in text.splitlines() if ln.strip().startswith(prefix)]
# [对每个元素做什么   for 循环变量 in 可遍历的东西   if 满足条件才要]
```

等价于普通写法：
```python
result = []
for ln in text.splitlines():
    if ln.strip().startswith(prefix):
        result.append(ln.strip())
```

### 6. 什么是「f-string」？
字符串前面加 `f`，就可以用 `{变量名}` 把变量的值**嵌进字符串里**：

```python
name = "SW-Core"
print(f"[{name}] 连接中")     # 输出：[SW-Core] 连接中
```

### 7. 什么是「try / except」？
**尝试**做一件事，如果**出错**就进入 except 分支处理，而不是让程序直接崩溃。

```python
try:
    do_something()     # 可能出错
except Exception as exc:   # 出错时把错误信息存到 exc
    print(exc)         # 处理错误
```

### 8. 什么是「with」？
`with` 叫**上下文管理器**。它能保证「用完自动关闭」资源（文件、网络连接等），不用手动 close。

```python
with open("a.txt", "r") as f:
    data = f.read()
# 到这里文件自动关闭了
```

### 9. 什么是「@property」？
把「一个函数」伪装成「一个属性（变量）」。调用时**不加括号**，像取变量一样：

```python
@property
def rate(self) -> float:
    return 100.0

# 用的时候：device.rate（不是 device.rate()）
```

好处：`rate` 的值是**根据其他数据实时算出来**的，不用事先存。

### 10. 什么是「lambda」？
lambda = 一句话版的小函数，常配合 `sorted`、`key=` 用来指定排序规则：

```python
sorted(items, key=lambda x: x[1])
# 意思是：按每个元素 x 的第 1 个下标位置的值来排序
```

### 11. 什么是「*args / **kwargs 解包」？
- `def f(*args)`：接收任意多个「位置参数」，打包成元组 args。
- `def f(**kwargs)`：接收任意多个「键=值 参数」，打包成字典 kwargs。
- `f(**params)`：反过来，把一个**字典**展开成「键=值 参数」传进去。

```python
params = {"host": "192.168.100.1", "port": 22}
ConnectHandler(**params)
# 等价于 ConnectHandler(host="192.168.100.1", port=22)
```

## 一、整体流程（先把地图印在脑子里）

```
main.py (入口，指挥一切)
   │
   ├─ 1. 采集：collector.collect_all() → 用 Netmiko 登录每台设备，拿到
   │      「display current-configuration」的原始文本（一堆字符串）
   │
   ├─ 2. 解析：parser.parse_config() → 把原始文本「结构化」，提取设备名/VLAN/接口/管理IP等
   │
   ├─ 3. 审计：auditor.build_report() → 对每台设备 × 每条规则(rules.yaml)做比对，

   │          report_excel.render() → 生成 Excel 报告
   │

```

`try/except` 在这里的作用是：「先试第一种，不行就换第二种」。**面试问点：为什么两个导入路径？因为脚本既能当模块也能当入口，两种方式都要兼容。**

```python

```
`__file__` 是 Python 自动给的变量，表示**当前文件在哪**。
`.resolve()` 把路径转成绝对路径（去掉 `..` 和符号链接），`.parent` 是它的**上一级目录**。
所以 `BASE_DIR` = `compliance/` 这个目录的绝对路径。
**作用**：后面所有相对文件（samples/、rules.yaml 等）都以它为基准找，这样**不管在哪个目录运行脚本都能找到文件**。这是很关键、面试也常问的写法。

```python

```
`/` 运算符在 pathlib 里就是「拼接路径」。`SAMPLES_DIR` = `compliance/samples` 目录。


一个**字典**（键值对）：设备名 → 角色。files 模式读取 samples 时，用它把文件名映射成中文角色名。

定义函数 `load_config`，参数 `path` 默认是 `None`，返回字典。
- `Path | None`：参数可以传路径，也可以不传（传 None）。


```python
第 119~120 行：if __name__ == "__main__":  sys.exit(main())
```

**Python 最经典的入口写法**，面试必问。
- `__name__`：Python 自动给的变量。当**直接运行这个文件**时，它的值是 `"__main__"`；当被别的文件 import 时，它的值是模块名（不是 `__main__`）。
- 所以这行的意思是：**只有当我被直接运行时才执行 main()**。被 import 时不会自动跑，避免副作用。
- `sys.exit(main())`：把 main() 的返回值（退出码）交给系统，程序结束。

**面试可以说**：这是整个项目里唯一与真实设备交互的部分，底层是 Netmiko → paramiko → SSH 协议。

```python
第 6 行：from __future__ import annotations
```
同 main.py，兼容类型注解的保险丝。

```python
第 8~9 行：import pathlib / import sys
```
- `pathlib`：路径处理
- `sys`：往错误流打印

```python
第 11~12 行：import yaml  /  from netmiko import ConnectHandler
```

- `from netmiko import ConnectHandler`：**netmiko 是最关键的第三方库**，`ConnectHandler` 是一个函数，给它设备参数它就能建立 SSH/Telnet 连接。netmiko 是对 paramiko 的封装，专门为网络设备的命令行交互做了优化。

正则匹配。逐段看：
- `r"..."`：**原始字符串**，反斜杠不会被转义，写正则必用
- `^sysname`：行首必须是 `sysname`（`^` = 行首）
- `\s+`：一个或多个空白（空格/tab）

- `re.MULTILINE`：让 `^` 匹配**每一行的开头**（否则只匹配整个文本的开头）
- 匹配结果存在 m。如果匹配到，`m.group(1)` 就是括号里抓到的内容 = 设备名。


- `pass_count / len(results) * 100` = 通过/总数 × 100 = 百分比
- `round(x, 1)` = 四舍五入保留 1 位小数


  权重取不到就用 9（排最后，防未知值）。
- **面试可讲**：用 `key=` 指定排序依据，lambda 拿到每条规则，查它严重性对应的数字。

```python
第 72 行：def _handle(client, hostname, config_text) -> None:
```
真正处理**一个** SSH 连接。

```python
第 73 行：transport = paramiko.Transport(client)
```

```python
第 74 行：transport.add_server_key(HOST_KEY)
```

告诉传输层「用这把主机密钥」。

**启动 SSH 服务端**，并把上面定义的接口类实例传进去。paramiko 会调用它的回调方法完成握手认证。

```python
第 76 行：channel = transport.accept(30)
```
等待客户端建立通道（shell），超时 30 秒。返回 channel（数据传输通道）。

```python
第 77~79 行：if channel is None:  transport.close()  return
```
30 秒内没等到通道（客户端没发请求）→ 关闭连接，退出函数。

```python
第 81 行：channel.send(f"<{hostname}>")
```
**发送登录提示符** `<SW-Core>`。这是模拟设备的第一个输出，Netmiko 靠它识别「设备就绪」。

```python
第 82 行：buf = ""
```
缓冲区，攒收到的数据（网络数据可能分块到达）。




按第一个换行切开：左边是完整的一行命令，右边剩下的继续留在 buf。

去空白。


**为什么必须回显？** 这是踩过的坑：Netmiko 默认要确认「命令回显」来验证命令发出去了（cmd_verify 机制）。不回显 Netmiko 会超时。`\r\n` = 回车+换行（终端换行标准）。


**为什么必须回提示符？** Netmiko 靠 `>` 字符识别命令是否执行完（find_prompt 机制）。不回提示符 Netmiko 会一直等、最后超时。**这是 mock 服务器能否跑通的关键。**


任何异常（比如客户端突然断开）都忽略——mock 服务器要保持健壮。

```python

```
无论正常还是异常，**最后都关闭传输层**，释放资源。

程序主入口。

```python
第 106 行：threads = [threading.Thread(target=serve_device, args=(name, port), daemon=True) for name, port in DEVICES]
```
列表推导式：为每台设备创建一个线程，各自监听不同端口。`args=(name, port)` 是元组解包。

```python
第 107~108 行：for t in threads:  t.start()
```

```python
第 109 行：print("[mock] 伪华为 SSH 服务器已启动，Ctrl+C 退出。")
```

```python
第 110~112 行：try:  for t in threads:  t.join()
```
`join()` = 等待线程结束。主线程在这里**阻塞住**，让服务器一直运行。

```python
第 113~114 行：except KeyboardInterrupt:  print("\n[mock] 已退出。")
```
用户按 Ctrl+C 时捕获中断信号，打印退出信息（而不是报错）。

入口写法，同上——只有直接运行时才启动服务器。

## 附：面试「一分钟讲这个项目」话术

> 我做一个**网络设备配置合规性自动审计系统**。在华为 eNSP 上搭了 4 台 S5700 的三层园区网，
> 用 **Netmiko 批量 SSH 登录**每台设备，采集运行配置；然后用**正则解析引擎**把配置文本结构化，
> 按 **10 条数据驱动的合规规则**（SNMP/AAA/高危端口/日志/ACL）逐条比对，算出每台设备和整体的合规率；
> 输出 **HTML + Excel 双格式报告**，合规率低于阈值时**自动推企业微信告警**。
> 整个流程分三档验证：离线样例、mock 伪 SSH 服务器、eNSP 真机，全部跑通。
> 规则放在 YAML 里，**改规则不改代码**，可扩展性好。

**可能被追问的点和答案**：
- **Netmiko 是什么？** 一个封装了 SSH/Telnet 的 Python 网络设备交互库，按 `device_type` 自动适配华为/思科等设备的命令交互方式。
- **为什么用正则解析？** 设备配置是文本，规则是"配置里有没有某段特征"，正则最直接、零依赖。
- **规则为什么放 YAML？** 数据驱动设计，规则和代码解耦，审计人员能自己加规则。
- **怎么保证一台设备挂了不影响整体？** collect_all 里每台设备 try/except 单独处理，失败打印并跳过。
- **怎么测试的？** 三层：单元测试（8 个用例断言合规梯度）、mock 伪 SSH 服务器端到端、eNSP 真机验证。
- **安全考虑？** 报告里所有内容过 html.escape 防注入；config.yaml（含 webhook）进 .gitignore 不入库。



## 面试最该记住的 5 个点（背熟这些就够）

1. **整体流程**：采集 → 解析 → 审计 → 报告 → 告警，五步能复述
2. **`if __name__ == "__main__"`**：只有直接运行时才执行 main，被 import 不会自动跑
3. **规则数据驱动**：规则放 `rules.yaml`，改规则不改代码 —— 这是项目核心亮点
4. **为什么 `field(default_factory=list)`**：避免所有实例共享同一个列表
5. **mock 服务器为什么能跑通**：必须回显命令 + 每条命令后回提示符，否则 Netmiko 超时（这是真踩过的坑，讲出来很加分）
